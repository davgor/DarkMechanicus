## Discoveries

- **Sidebar count after Rescan** (DM-351): the sidebar row reads the project once per mount, so its repository count is stale after Rescan until a reload.
- **Validation lists missing repositories as choices** (DM-348): the `missing_repo` message names repositories a rescan marked missing.
- **An optional ticket accepted after the acceptance node** (DM-356, DM-357, DM-358): it adds a touched repository the node's increments did not name, so `increment_merged` and `definition_of_done` become unmet, and an accepted node cannot be claimed again in the run. Not exercised past the gate.
- **Touched repositories are read from the epic's active or latest run** (DM-355, DM-358), not from the run being evaluated.
- **Packet path vs `gitFor` path** (DM-355): the packet joins the project root and the name, while `gitFor` resolves real paths; they differ behind a symlinked root.
- **Where orchestrator agents put worktrees** (c16): the live agent asked for worker and integration worktrees under `/tmp`; the guides could name a location next to the folder so a scratch-only approval policy does not push workers into the child checkout.
- **`multi_repo` on an already set-up single repository** (DM-346): returns the existing project with no error saying the layout was ignored.
- **First-run kickoff** (DM-360): repository branches are bound at `start_run`, after the kickoff is sent, so a first-run kickoff lists only the epic branch.
- **Panel grouping** (DM-362): the acceptance panel groups Definition of Done rows by targeted repositories; the gate uses repositories with accepted tickets.
