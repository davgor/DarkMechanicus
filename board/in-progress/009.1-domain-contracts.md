# 009.1 — Domain contracts, ids, hashing, errors

Shared vocabulary for every entry point: three-state statuses, plan bundle types, read-model views, `CommandApi`, error codes; collision-resistant ids, canonical-JSON content hashes, `DomainError`.

## Acceptance criteria

- [ ] `src/shared/domain/{status,bundle,views,api,errors}.ts` define the contracts used by core, MCP, and desktop
- [ ] Stable ids are collision-resistant (`<prefix>_<time><random>`), validated by `STABLE_ID_PATTERN` (tested)
- [ ] `contentHash` is stable across object key order and `prettyJson` output is key-sorted (tested)
- [ ] Unknown thrown values map to `internal`; domain errors keep code/message/details (tested)
