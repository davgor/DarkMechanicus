# 009.4 — Portable records and crash-safe Save finalizer

Outbox-driven finalizer writes complete immutable snapshots, then atomically replaces the pointer; epic state and run history use the same machinery. Interruption at every write boundary preserves the last good state and retries idempotently.

## Acceptance criteria

- [ ] Snapshot, pointer, epic-state, and run-history files are key-sorted JSON validated by schemas (tested)
- [ ] A fault injected at each write boundary (temp write, fsync, rename, read-back, pointer rename, DB commit) leaves the previous pointer and snapshot intact and the entry pending (tested)
- [ ] Re-running the flush after a fault completes the save with identical content (tested)
- [ ] Save reports `saved` only after the new revision is recoverable from repository records; otherwise `pending` with the draft kept (tested)
